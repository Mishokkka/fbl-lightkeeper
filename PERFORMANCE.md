# Производительность Lightkeeper

## Проверка 0.4.0

Передающие огонь источники входят в событийный индекс активных токенов. Подбор выполняется при открытии/изменении панели и при игровом действии; дополнительного heartbeat, обхода неактивных актёров и таймера поиска соседей нет. Движение донора или выбранного токена обновляет доступность с объединением событий в одну перерисовку. Постороннее движение и контрольные сохранения панель не перестраивают. Геометрия препятствий кэшируется по Scene и сбрасывается при изменении стен. Однократная миграция старого формата на ГМе отдельно просматривает инвентари и сохранённые огарки, затем помечается завершённой.

Повторный синтетический прогон на том же стенде: 6 источников / 4000 неактивных токенов — медиана 0.249 мс и p95 0.517 мс с закрытой панелью; 0.317 / 0.543 мс с открытой. Для 60 источников / 10000 неактивных — 1.702 / 2.309 мс. За 120 проходов шести источников остаются 720 Item + 720 Token, 110160 байт полей, 0 чтений неактивных токенов, 0 полных рендеров на checkpoint. У шести игроков с закрытой панелью — 0 интервалов и периодических записей. Абсолютные времена зависят от запуска; структурные инварианты проверяются тестами.

## Проверка 0.3.0

Повторный локальный прогон 29 октября 2026 года (Windows / Node.js 24.16.0) после добавления розжига через Bonus и звуков:

| Сценарий | Медиана прохода, мс | p95, мс | Чтений неактивных токенов | Полных рендеров панели |
| --- | ---: | ---: | ---: | ---: |
| 6 источников, панель закрыта | 0.237 | 0.606 | 0 | 0 |
| 6 источников, панель открыта | 0.493 | 0.946 | 0 | 0 |
| 60 источников | 1.693 | 2.524 | 0 | 0 |

За 120 проходов шести источников: те же 720 Item + 720 Token и 110160 байт полей обновлений. Новые настройки звука не пересылаются на checkpoint. У каждого из шести игроков с закрытой панелью остаются 0 интервалов и 0 периодических записей. Звук рассылается только при включении/выключении, не на тиках часов; воспроизведение и затухание используют штатный Sound без дополнительного интервала модуля. Отдельный тест подтверждает получение сигнала шестью клиентскими контекстами без дублирования.

Абсолютное время между запусками стенда колеблется; гарантиями тестов являются структура работы и число операций, а не порог в миллисекундах. Ограничения синтетического замера, указанные ниже, сохраняются.

## Исходное сравнение 0.2.0 → 0.2.2

Замер 29 октября 2026 года, Windows / Node.js 24.16.0. Исходная версия — PR №1, коммит `005a5b9` (0.2.0). Один и тот же адаптер документов и событий используется для обеих версий.

## Что изменено

- Один обход flags при подключении клиента. Затем индекс активных источников обновляется по событиям Token/Scene; неактивные актёры не загружаются таймером. Поиск занятого бака — через индекс.
- Правила библиотеки компилируются один раз и сбрасываются при изменении настроек. Названия и UUID кэшируются с проверкой переименования; количество топлива всегда читается заново. Публичный API возвращает отдельную копию библиотеки.
- Один 5-секундный таймер только на выбранном ГМе, только при конечных активных источниках, без паузы. Бесконечные источники не требуют периодических записей.
- Остаток в Item и timestamps в Token сохраняются узкими обновлениями с `render:false`. Полные конфигурация, runtime и исходный свет не пересылаются каждые 5 секунд. Период сохранения не увеличен.
- Разные инвентари сохраняются параллельно. Общий инвентарь сохраняет свою последовательную очередь; новый heartbeat не перекрывает ещё незавершённый.
- Обновления позиции и посторонних документов не перестраивают панель. Часы обновляют отдельные DOM-узлы; несколько структурных событий объединяются в одну перерисовку. История пауз освобождается, когда старые границы больше не нужны.
- Часы панели существуют только для конечного работающего источника в открытом окне; в паузе и скрытой вкладке они останавливаются. На клиенте игрока с закрытой панелью нет фоновых интервалов модуля.
- В 0.2.2 проверки версии источника защищают продолжение асинхронных записей, а изменения конфигурации используют ту же очередь инвентаря. Уведомления не блокируют очередь. При отсутствии ГМа останавливаются и часы панели. Это проверки только активных документов, без повторного обхода мира.

## Результаты стенда

В основном сценарии — ГМ, шесть источников в разных инвентарях, по 100 предметов, 20 сцен и 4000 неактивных токенов. После пяти прогревочных проходов измерены 120 проходов: десять минут моделируемого расхода. Нагрузочный сценарий увеличивает число источников до 60 и число неактивных токенов до 10000.

| Версия / сценарий | Медиана прохода, мс | p95, мс | Чтений неактивных токенов | Полных рендеров панели |
| --- | ---: | ---: | ---: | ---: |
| 0.2.0, панель закрыта | 3.476 | 4.766 | 480000 | 0 |
| 0.2.2, панель закрыта | 0.184 | 0.324 | 0 | 0 |
| 0.2.0, панель открыта | 23.433 | 25.837 | 480000 | 1440 |
| 0.2.2, панель открыта | 0.235 | 0.363 | 0 | 0 |
| 0.2.2, 60 источников | 1.484 | 2.6 | 0 | 0 |

Для шести источников за 120 проходов число записей осталось **720 Item + 720 Token**: экономия не получена за счёт ухудшения сохранения топлива. Сумма JSON-полей обновлений уменьшилась с **699120 до 110160 байт** — примерно в **6,35 раза**. На один 5-секундный проход приходится около **918 байт** полей. Это данные до сетевых обёрток, метаданных и рассылки получателям, а не измеренный трафик сети.

В адаптере старая версия запрашивала обычную обработку рендера на всех 1440 записях. Новая передаёт `render:false` на каждом контрольном сохранении и не запрашивает такие перерисовки. Поддержка этого параметра проверена по установленным исходникам Foundry 13.351; система Forbidden Lands 13.0.5 не переопределяет соответствующую обработку потомков.

Для каждого из шести отдельных клиентских контекстов P1–P6 с закрытой панелью: **0 интервалов, 0 периодических записей и 0 чтений неактивных токенов**. При этом они по-прежнему получают изменения документов от ГМа.

## Что подтверждают проверки

Тесты проверяют инварианты производительности, а не пороги времени, зависящие от компьютера: нет повторных обходов мира и чтений библиотеки на heartbeat, нет фоновых интервалов у игроков, узкие поля и `render:false`, фильтрация посторонних событий, объединение перерисовок, освобождение индексов и смену ГМа. Отдельно проверяется параллельное сохранение шести медленных инвентарей без наложения heartbeat.

`npm run benchmark` повторяет нагрузочные сценарии. Для сравнения с прежней версией:

```text
node tests/benchmark.mjs --baseline=путь-к-копии-0.2.0
```

## Граница вывода

Это замер JavaScript контроллера, HTML-рендереров и имитации document hooks. Время подготовки моделей Foundry, настоящая сеть, дисковая база, работа сторонних модулей, WebGL и FPS сцены здесь не измерены. Рендеры в таблице — обращения на стенде, а не фактические кадры браузера. Поэтому абсолютную гарантию FPS для любого мира эти цифры не дают.

Для 5–6 игроков с одним источником на персонажа у самого учёта времени убраны повторяющиеся тяжёлые операции: на игроках остаётся только отображение открытой панели, на ГМе — небольшой проход раз в 5 секунд. Если узким местом становится именно освещение сцены, источник можно настроить без анимации; учёт топлива от этого не меняется.
